## Section 21 — UI / operator controls

User frontend `MultiAssetPanel` (per connected account): market families with machine reasons, permission health
(withdraw shown "Not required"), topology + routes, **Auto Trading (per bot) shown separately from Auto Capital
Routing**, routing-policy form with validation, plan → explicit approve & execute (idempotency key
`plan_id + observed_at_ms`), FX instrument four-state badges. Masked-key fragments are no longer rendered anywhere
(BrokerConnection, BotDetails, BotInstanceRow). Admin frontend `CATI Research & Certification` page is read-only.
View-model logic in `src/utils/multiAssetView.ts`, tested by `src/tests/multiAssetView.test.ts`.

## Section 22 — certification and holdout rules

Existing and reused: `PolicyFreezeManifest`, `HoldoutRegistry` (RESERVED→OPENED→BURNED, a burned holdout is never
reusable), threshold tighten-only configuration, forward-demo PASS only when *both* minimum days and minimum executed
trades are met, crypto / FX universes separate. Gap closed: `certification/holdout_guard.py` — a pure
`pre_holdout_readiness` (dataset not acquiring, manifest frozen, complete, quality, mapping frozen, real data only,
policy hash frozen and canonical, code identity, FULL/MEDIUM pre-holdout PASS, evidence produced) and an explicit,
recorded `authorize_holdout` governance event. The certification pipeline's holdout stage now returns `NOT_RUN`
(`HOLDOUT_AUTHORIZATION_REQUIRED`, `RESERVED_UNTOUCHED`) without that event. Authorization never opens a holdout, and
no API route can call it. No threshold, policy identity or `RESEARCH_DEFAULT_V1` change.

## Section 24 — test matrix

`scripts/cati_test_matrix.py` maps families 24.1–24.14 plus Sections 20/21/25/26/27 to test files and name patterns and

## Section 25 — security

Verified existing: Fernet-encrypted credentials (key from `BROKER_SECRET_KEY`, never stored), redaction filter +
`redact_text` / `redact_exception` in both backends, structured-event sanitization, no withdraw-named client method or
mutating withdraw request, trade and internal-transfer permissions distinct, Bybit `recv_window` 5000 with a single
dispatch per mutation (no blind replay), BingX fresh-timestamp signing, broker-health clock-drift check, in-flight
transfer storm block, tenant/account/intent lineage on mutations. Fixed: UI rendered masked-key prefixes. Added:
least-privilege recommendation + IP-allowlist guidance on market-status.

Structured events via existing `log_stage` for transfer plan / BLOCKED / FAILED / UNKNOWN / SUBMITTED. Alerts via the
existing `alerts` table (`app/ops/multi_asset_alerts.py`, de-duplicated by trace id, bounded metric labels):

its runtime FX-context source is not yet in the live path). Loop can be disabled with `MULTI_ASSET_ALERTS_ENABLED`.
Research identity hashes are independent of the wall clock (tested).
